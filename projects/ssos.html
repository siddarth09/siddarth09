Overview

Software-defined
space station

Space Station OS (SSOS) is an open-source platform built on ROS 2 to unify the development, simulation, and real-time control of modular space station subsystems. Inspired by the ISS, each subsystem is a standalone ROS 2 node with standardised interfaces — making the system flexible, testable, and hardware-ready.


The platform was featured by Northeastern University in February 2026 for its contribution to open-source space infrastructure software.

ECLSS — Life Support

Keeping humans
alive in orbit

The ECLSS simulation models the three core processes needed to sustain life: removing CO₂ from the cabin, generating fresh oxygen, and recovering clean water from waste. Each is a separate ROS 2 node connected by well-defined service and topic interfaces.

ECLSS Closed-Loop Flow
Cabin Air ──CO₂──► ARS / CDRA ──CO₂ stored──► Sabatier Reactor ──H₂O + CH₄──► WRS
↑ H₂ feed ↓ product H₂O
Cabin Air ◄──O₂── OGS (electrolysis) ◄──clean H₂O── WRS / WPA ◄──wastewater── Crew / Systems
ARS
Air Revitalisation System
Simulates the Carbon Dioxide Removal Assembly (CDRA). CO₂ is scrubbed from cabin air, stored, and optionally routed to the Sabatier reactor. Contaminant diagnostics published via ROS 2 topics.
Interface Action server + service
Output topic /co2_storage_telemetry
Failure modes Modelled
OGS
Oxygen Generation System
Models water electrolysis and the Sabatier reaction. O₂ is generated and returned to the cabin; H₂ byproduct is fed back to ARS. Integrates with both ARS and WRS for full loop closure.
Reaction H₂O → H₂ + ½O₂
Sabatier CO₂ + 4H₂ → CH₄ + 2H₂O
Diagnostics Published
WRS
Water Recovery System
Inspired by the ISS Urine Processor and Water Processor Assemblies. Wastewater is purified through staged processing back to product water, closing the loop with OGS.
Stages Multi-stage purification
Grey water Handled
Service /request_water
TCS — Thermal Control

Managing heat
at the extremes

In low Earth orbit, a space station swings between +120°C in sunlight and −160°C in shadow every 90 minutes. The TCS simulation abstracts the ISS Active Thermal Control System using configurable thermal nodes and RK4 numerical integration for accurate dynamic behaviour.

TCS — Thermal Node Simulation Loop
YAML Config ──nodes + links──► TCS Node ──ΔT every tick──► RK4 Integrator
(heat capacity, internal power, conduction coefficients) (dT/dt = Q_in − Q_out / C)

RK4 Integrator ──T_node[]──► Threshold Check ──if T > T_max──► Cooling Loop (water/ammonia loop)
──FDIR event──► /diagnostics
  • Thermal nodes represent equipment with temperature, heat capacity, and internal power dissipation
  • Thermal links define conduction-based heat flow between adjacent nodes
  • RK4 integration provides accurate temperature evolution over simulation time
  • Cooling logic activates dynamically when node temperature exceeds configured threshold
  • FDIR events (overheating, loop failure) published to /diagnostics for monitoring

Architecture

Hardware-ready
from day one

Every subsystem node exposes the same interface pattern — standardised ROS 2 topics, services, and action servers — so swapping a simulated node for a real hardware driver requires minimal code changes.

ROS 2 Interface Pattern (per subsystem)
Subsystem Node
├─ /telemetry topic (publish state @ rate)
├─ /request service (synchronous request)
├─ /control action (long-running ops)
└─ /diagnostics topic (FDIR events)
  • C++ and Python nodes within the same ROS 2 workspace
  • PyQt5 GUI panels for both crew and mission control views
  • Docker-based reproducibility for any contributor
  • GitHub-maintained with full documentation
