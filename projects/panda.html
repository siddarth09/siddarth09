System overview

Classical
Intelligence

The classical pipeline decomposes manipulation into three independently debuggable stages: perceive the object, plan a collision-free path, and execute with closed-loop IK control. Each stage is transparent — you can see exactly what the robot knows and why it moves the way it does.


This explicitness is the key design philosophy. Unlike end-to-end learned policies, every failure mode is traceable to a specific module — a critical property when deploying on real hardware.

Classical Pipeline

Four-Stage
Pipeline

Each stage is a discrete, replaceable module. The perception block feeds the planner; the planner feeds the IK controller; the controller feeds the actuators. Failures localise instantly.

Autonomy Stack
Camera → Perception → World Model → Planner → IK → Motors

Every module exposes a clean ROS 2 interface. Swapping HSV detection for a learned detector requires zero changes downstream.
01
HSV Perception
RGB frames converted to HSV space and thresholded. Dominant contour extracted; centroid computed via image moments (m₁₀/m₀₀, m₀₁/m₀₀). Projected to 3D with known intrinsics, then transformed to robot base frame via ROS 2 TF.
OpenCV · ROS 2 TF · Camera Intrinsics
↓ 3D object pose
02
RRTConnect Motion Planner
Sampling-based planning in the 7-DoF configuration space C ⊂ ℝ⁷. Two rapidly-exploring random trees grow from start and goal until they connect. Path is time-parameterised and collision-checked against the scene geometry.
OMPL · RRTConnect · Collision Checking
↓ joint trajectory
03
Jacobian IK — Pinocchio
Damped least-squares inverse kinematics. Task-space error resolved via the damped pseudoinverse: q̇ = Jᵀ(JJᵀ + λ²I)⁻¹ε. Pinocchio provides analytical Jacobians and efficient frame-level kinematics for stable real-time control.
Pinocchio · Damped Least Squares · Real-time
↓ joint commands
04
State Machine Execution
Explicit sequencing: reach → grasp → lift → place → retreat. Each state triggers the planner and IK controller with a new target pose. Failure detection at each transition.
ROS 2 · State Machine · Franka Interface
IK Formulation

Inverse
Kinematics

Forward kinematics define a nonlinear map from joint space to task space. Inverse kinematics solves the reverse: given a desired end-effector pose, find the joint configuration that achieves it. Pinocchio solves this iteratively using the analytical Jacobian.

Forward Kinematics
x = f(q) ẋ = J(q) · q̇
Damped Least-Squares IK
q̇ = Jᵀ(JJᵀ + λ²I)⁻¹ · ε ε = x* − x (task-space error) λ = damping factor (prevents singularities)
Pinocchio IK — Core Loop
# Load robot model model, data = pinocchio.buildModelFromUrdf(urdf) # Current end-effector pose pinocchio.forwardKinematics(model, data, q) x_ee = data.oMf[ee_frame].translation # Task-space error eps = x_target - x_ee # position error eps_R = log3(R_target @ R_ee.T) # orientation error # Analytical Jacobian from Pinocchio J = pinocchio.computeFrameJacobian(model, data, q, ee_frame) # Damped least-squares IK step damp = 1e-3 dq = J.T @ inv(J @ J.T + damp*eye) @ eps # Update and publish joint commands q = q + dt * dq publish_joint_cmd(q)
  • Damping λ prevents instability near kinematic singularities
  • Pinocchio provides analytic Jacobians — no finite differencing
  • Full 6-DoF control: position + orientation error minimised
  • Runs at control rate — fast enough for real-time execution

HSV Detection → 3D Pose
# Convert to HSV and threshold hsv = cv2.cvtColor(frame, COLOR_BGR2HSV) mask = cv2.inRange(hsv, lower_hsv, upper_hsv) # Extract dominant contour contours, _ = cv2.findContours(mask, RETR_EXTERNAL, CHAIN_APPROX_SIMPLE) cnt = max(contours, key=cv2.contourArea) # Centroid via image moments M = cv2.moments(cnt) cx = int(M['m10'] / M['m00']) cy = int(M['m01'] / M['m00']) # Back-project to 3D (known depth + intrinsics) X = (cx - cx_intr) * depth / fx Y = (cy - cy_intr) * depth / fy Z = depth # Transform camera → robot base via TF p_robot = tf_buffer.transform(p_cam, 'panda_link0')
  • HSV thresholding — robust to brightness variation vs RGB
  • Image moments give sub-pixel centroid accuracy
  • ROS 2 TF handles all coordinate frame transforms
  • Fully replaceable with learned detector — same output interface
Motion Planning

Path Through
C-Space

Planning occurs in the 7-dimensional configuration space C ⊂ ℝ⁷. RRTConnect grows two trees simultaneously — one from start, one from goal — until a collision-free bridge is found. Far faster than single-tree RRT on high-DoF arms.

Connection Criterion
‖q_start − q_goal‖ < ε
  • Configuration space: C ⊂ ℝ⁷ — one dimension per joint
  • RRTConnect: bidirectional tree growth for faster convergence
  • Collision checking against full scene geometry at each sample
  • Path time-parameterised for smooth velocity profiles
  • OMPL handles all sampling, nearest-neighbour, and extension logic
  • Works directly with MoveIt 2 for ROS 2 integration
  • Replanning triggered automatically on detected collision
