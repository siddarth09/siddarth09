System overview

Built to
Race

This is not a simulation project. Every algorithm was deployed and validated on a real RoboRacer F1TENTH Ackermann platform — real constraints, real timing, real consequences for bad tuning.


The autonomy stack separates trajectory generation from execution: a fast rollout planner scores candidates against obstacle distance transforms, while MPC and MPCC handle precise closed-loop control.

Control architecture

Three
Sectors

01
Dynamic Rollout Planner
Samples steering commands across the feasible range and forward-simulates the bicycle kinematics over a fixed horizon using RK4. Each candidate is scored on obstacle clearance, curvature, and goal deviation. The best rollout is published as the MPC reference path.
RK4 · Distance Transform · Scoring
02
Nonlinear MPC Tracker
Solves a finite-horizon nonlinear optimisation problem every control cycle via CasADi and IPOPT. State includes pose and speed; controls are commanded speed and steering angle. Enforces actuator bounds and applies receding horizon control.
CasADi · IPOPT · Ackermann Model
03
MPCC Racing Controller
Augments MPC with a progress state θ along the centerline arc. Penalises contouring and lag errors while explicitly rewarding forward progress — the car "wants" to move fast, not just reduce reference error.
Contouring Error · Lag Error · Progress
Sector 01 — Planner

Rollout
Scoring

Steering commands δ are sampled across the feasible range and forward-integrated using RK4 over N steps. Any candidate whose minimum clearance drops below d_safe is immediately rejected. Surviving rollouts compete on a three-term objective.

Bicycle Kinematics
ẋ = v·cos(θ) ẏ = v·sin(θ) θ̇ = (v/L)·tan(δ)
Safety Rejection
Reject if mink∈[1,N] d(xₖ,yₖ) < d_safe
Rollout Scoring Objective
J(τ) = Σk=1..N d(xₖ,yₖ) − α · Σk=2..N |Δθₖ| ← curvature penalty − β · ‖[xₙ,yₙ] − g‖₂ ← goal attraction Clearance term — prefers paths far from obstacles Curvature term — discourages yaw oscillations Goal term — pulls endpoint toward target Output → nav_msgs/Path on /dynamic_trajectory
  • RK4 integration reduces drift vs Euler at high speed
  • Distance transform pre-computed from occupancy grid
  • Best rollout published as MPC reference each tick
  • Separates "what to do" from "how to execute"
Sector 02 — MPC

Nonlinear
Tracking

State x = [x, y, ψ, v]ᵀ. Controls u = [v_c, δ]ᵀ. The bicycle model includes a slip-angle approximation for more accurate high-speed cornering behaviour. IPOPT solves the constrained NLP; only the first control action is applied.

Slip Angle
β = arctan(Lᵣ/L · tan(δ))
MPC Cost
min Σk=0..N-1 ‖xₖ − xᵣₑ𝒻‖²_Q + ‖uₖ‖²_R + ‖xₙ − xᵣₑ𝒻‖²_Q𝒻 s.t. xₖ₊₁ = f(xₖ,uₖ) v_min ≤ vc ≤ v_max δ_min ≤ δ ≤ δ_max
CasADi / IPOPT Implementation
# Symbolic state + control variables x = MX.sym('x', 4) # [x, y, ψ, v] u = MX.sym('u', 2) # [v_c, δ] # Nonlinear bicycle model (with slip) β = atan2(Lr * tan(u[1]), L) ẋ = u[0] * cos(x[2] + β) ẏ = u[0] * sin(x[2] + β) ψ̇ = u[0] * cos(β) / L * tan(u[1]) # Receding horizon — apply u[:,0] to robot pub AckermannDriveStamped → /drive
  • Symbolic differentiation via CasADi — analytic Jacobians
  • IPOPT interior-point solver for constrained NLP
  • Warm-started each tick from previous solution
  • Robot pose from TF: map → ego_racecar/base_link
Sector 03 — MPCC

Racing
Line Control

MPCC adds a progress state θ (arc-length along the centerline). Rather than chasing waypoints, it balances a race-style tradeoff: staying near the line while maximising forward progress. The result is naturally faster lap times and cleaner cornering.

Contouring & Lag Errors
εc = sin(φ_cl)·dx − cos(φ_cl)·dy εl = −cos(φ_cl)·dx − sin(φ_cl)·dy
MPCC Objective
min Σ qc·εc² + ql·εl² − qθ·(θk − scl,k) ← progress reward + ‖uₖ‖²_R
Why MPCC beats standard MPC on track
Standard MPC minimises distance to reference waypoints → fights to reach each point in sequence → can brake unnecessarily before corners MPCC minimises contouring error (stay near line) maximises progress (θ → s_cl reward) → naturally cuts corners when optimal → stable at speed — no waypoint chasing ROS topics: /racing_trajectory ← arc-length parameterised /mpcc_predicted_horizon ← MarkerArray viz /drive ← AckermannDriveStamped
  • Progress state θ augmented into system state vector
  • θ updated: θₖ₊₁ = θₖ + vₖ·Δt at each horizon step
  • Contouring error penalises lateral deviation from line
  • Lag error penalises falling behind the reference arc
